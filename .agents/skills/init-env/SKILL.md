# 워크스페이스 환경 초기화 (`00_artifacts` ~ `04_rag_database`, `.agents/`)

사용자가 `/init-env`를 실행하거나 현재 워크스페이스에 5대 번호형 디렉터리(`00_artifacts/`, `01_input_data/`, `02_output_data/`, `03_scripts/`, `04_rag_database/`)와 `.agents/` 커스터마이징 환경 구축을 요청할 때 이 스킬을 사용합니다.

## 스캐폴딩 절차 (Scaffolding Procedure)

1. **워크스페이스 경로 확인**:
   - 현재 워크스페이스 디렉터리를 확인합니다.
   - 5대 번호형 디렉터리가 이미 존재하는지 점검합니다.

2. **스캐폴딩 실행**:
   - 워크스페이스에서 스캐폴딩 스크립트를 실행합니다:
     ```bash
     python "$HOME/.gemini/config/skills/init-env/scripts/scaffold_env.py" --target-dir "<workspace_path>"
     ```
   - 스크립트 실행이 불가능한 경우, 파일 생성 도구를 사용하여 디렉터리와 템플릿 파일을 직접 생성합니다.

3. **스캐폴딩되는 5대 번호형 파일 구조**:
   - **`00_artifacts/` (오직 Antigravity 에이전트 작업 산출물 전용)**:
     - `00_artifacts/README.md`: 에이전트 산출물 중앙 인덱스 테이블 및 가이드.
     - `00_artifacts/plans/`: 구현 계획서 및 기능 기획서 (`plan_([주제명])_[YYMMDD]_rev[NN].md`).
     - `00_artifacts/walkthroughs/`: 작업 완료 보고서 및 테스트 검증 리포트 (`walkthrough_([주제명])_[YYMMDD]_rev[NN].md`).
     - `00_artifacts/reports/`: 에이전트가 자체 조사·분석한 심층 기술 리포트 (`report_([주제명])_[YYMMDD]_rev[NN].md`).
     - `00_artifacts/designs/`: 시스템 아키텍처 및 상세 설계서 (`design_([주제명])_[YYMMDD]_rev[NN].md`).
   - **`01_input_data/` (실무 투입 자료 저장소 - 2개 폴더)**:
     - `01_input_data/README.md`: 투입 자료 보관 개요, 일련번호 규칙 및 인덱스 테이블.
     - `01_input_data/00_received/`: 외부 고객사, 시험실, 협력사에서 전달받은 원천 자료 (원본 파일명 보존 허용, 사양서, CAD/STEP 도면, 물성치 시트, 메쉬/격자, 측정 데이터 등).
     - `01_input_data/01_references/`: 
       - **에이전트 작업 지시 투입 자료**: 사용자가 에이전트에게 구체적인 작업을 지시하기 위해 작성·준비한 작업 요구사항 정의서, 작업 지시 메모, 해석 가이드라인, 프롬프트용 참조 텍스트.
       - **엔지니어링 표준 기준**: 솔버 공식 매뉴얼, 설계 기준, 산업 규격(ISO/ASME/ASTM).
       - **사용자 조사 리서치 자료**: 업무 수행 중 사용자가 직접 탐색·수집한 참고 논문, 장비 카탈로그, 기술 데이터시트, 웹 포럼 해결 팁.
   - **`02_output_data/` (실무 엔지니어링 자산 저장소 - 작업 흐름 3단계)**:
     - `02_output_data/README.md`: 실무 자료 보관 개요, 일련번호/버전 관리 안내 및 인덱스 테이블.
     - `02_output_data/00_data/`: 1단계 가공·정제 입력 데이터 및 시뮬레이션 솔버 해석 결과 수치 데이터 (`excel_`, `csv_`).
     - `02_output_data/01_figure/`: 2단계 시각화 플롯 차트, 유선/온도장 콘투어 이미지, 격자/도면 캡처, 솔버 실행 로그 (`plot_`, `image_`, `log_`).
     - `02_output_data/02_reports/`: 3단계 최종 기술 완료 보고서, 고객 보고용 발표 슬라이드, 배포용 요약 문서 (`doc_`, `ppt_`, `pdf_`).
   - **`03_scripts/` (엔지니어링 자동화 스크립트 저장소)**:
     - 데이터 전/후처리 Python 스크립트(`py_`), Fluent/CFX 저널(`.jou`, `.ccl`), 배치 자동화 쉘 스크립트(`sh_`).
   - **`04_rag_database/` (RAG 지식 베이스 및 벡터 인덱스 저장소)**:
     - `04_rag_database/README.md`: RAG 관리 원칙 및 `rag-builder` 스킬 연동 가이드.
     - `.gitkeep`: 클린 베이스 디렉터리 유지 (세부 타깃 인덱스, 메타데이터, `.gitignore`는 `rag-builder` 스킬이 동적으로 생성/관리).
   - **`.agents/` (에이전트 거버넌스 및 커스터마이징)**:
     - `.agents/README.md`, `agents.md`, `rules/`, `skills/`, `hooks.json`, `mcp_config.json`.
   - **`GEMINI.md`**: 전역 에이전트 행동 지침, 5대 번호형 트리, 저장소 격리 원칙, 일련번호/버전 명명 규칙.

## 자료 분류 및 보관 행동 지침 (Data & Artifact Guidelines)

### 1. 저장소 영역의 격리 원칙
1. **`00_artifacts/` (에이전트 프로세스 산출물 전용)**:
   - **오직 Antigravity의 작업 프로세스로부터 생성되는 산출물(Markdown .md 전용)**만을 저장합니다.
   - 사용자가 직접 작성한 파일이나 외부 원천 자료는 절대 보관하지 않습니다.
2. **`01_input_data/` (실무 투입 자료 저장소)**:
   - 외부 수신 원천 자료(`00_received/`)와 에이전트 작업 지시 자료, 가이드, 설계 규격, 수집 리서치 자료(`01_references/`)를 통합 보관합니다.
3. **`02_output_data/` (실무 엔지니어링 자산 저장소)**:
   - 실제 작업 결과로 생성된 비-마크다운 실무 파일들을 작업 순서에 따라 `00_data/`, `01_figure/`, `02_reports/`로 분리 보관합니다.
4. **`03_scripts/` (자동화 코드 저장소)**:
   - 전/후처리 및 배치 실행 자동화 코드를 독립 관리합니다.
5. **`04_rag_database/` (RAG 지식 베이스 저장소)**:
   - RAG 인덱스를 위한 베이스 저장소이며, 세부적인 인덱스 생성 및 타깃 격리는 `rag-builder` 스킬이 담당합니다.

### 2. 통합 파일명 명명 규칙: 일련번호 및 버전 관리 표준
대량 파일 생성 시에도 순서와 버전을 명확히 파악할 수 있도록 3자리 일련번호(`NNN`)와 리비전(`revNN`)을 필수로 결합합니다:

- **표준 템플릿**: `[포맷태그]_[일련번호]_([주제명])_[YYMMDD]_rev[NN].[확장자]`

#### 준수 수칙:
1. **구분자**: 하이픈(`-`) 사용 절대 금지, **언더스코어(`_`)만 반드시 사용**.
2. **포맷 태그(`[포맷태그]`)**: 파일 형식 식별자 (`excel`, `csv`, `plot`, `image`, `log`, `doc`, `ppt`, `pdf`, `py`, `jou`)
3. **일련번호(`[일련번호]`)**: 포맷별 **3자리 문서번호/생성 순번 (`001`, `002`, ... `999`)**. 생성 순서대로 자동 정렬 지원.
4. **괄호 표기**: 파일명 내의 `[주제명]` 부분은 반드시 괄호 `(` 와 `)` 로 직접 감쌈.
5. **날짜 표기(`[YYMMDD]`)**: 6자리 숫자 (예: `261028`).
6. **버전 표기(`rev[NN]`)**:
   - **최초 생성 시 무조건 `rev00` 기본 부여**
   - 동일 파일/주제 내용 갱신 시 **`rev01`**, **`rev02`**로 번호를 증가시켜 이력 추적.
7. **원천 자료 보존 예외 (Raw Preservation)**: `00_received/`에 저장되는 외부 수신 파일은 원본 파일명을 유지하는 것을 허용하며, `01_input_data/README.md`에 출처와 함께 등록합니다.
